## 7. Import, export, and batch

- [x] 7.1 Implement worker-based parsers for GeoJSON, KML/KMZ, GPX, CSV/TSV, WKT/WKB with size limits and safe parsing; verify with a fixture corpus including malicious KML (all of them, parsed in the compute worker: GeoJSON, KML and KMZ — unzipped with the platform's own DecompressionStream, no library — GPX, CSV/TSV, WKT, and hex WKB or PostGIS EWKB in either byte order, with a non-WGS 84 SRID refused and Z or M dropped. Files over 50 MB are refused before parsing and imports over 1,000,000 vertices refused; nothing a file points at is fetched — NetworkLinks, external entities, links — and what was ignored is named; descriptions are shown as inert text. Every tool with a list of points has an Import button and takes a dropped file. Gated by `apps/web/test/import.test.mjs` and `import-rows.test.mjs`, including a hostile KML, a KMZ built in the test, truncated and projected WKB.)
- [x] 7.2 Implement the CSV column-mapping dialog with swap detection and CRS choice; verify the swapped-columns scenario (importing a CSV or TSV asks which columns are latitude and longitude, starting from the headers; when the column named latitude holds values beyond ±90 it says the columns look swapped and offers a one-click Swap; each row must read as a coordinate or the import names the line that does not. The CRS choice takes a CSV as WGS 84 degrees, UTM (WGS 84, zone and hemisphere), or State Plane (NAD83, zone and unit), and converts eastings and northings through the core's own inverse tools in one batch; a State Plane import says its latitudes are NAD83. A GeoJSON declaring a WGS 84 UTM zone is converted the same way, and any other declared system is refused by name. `apps/web/test/crs.test.mjs`; tried in the browser: a 1 km UTM grid square imports as 1.000620 km², the grid scale factor at that easting.)
- [x] 7.3 Implement geometry validation and repair on import; verify the unclosed-ring scenario (unclosed rings are closed, repeated consecutive vertices removed, and outer rings wound counter-clockwise per RFC 7946, each reported; a ring that crosses itself is reported and never passed on as valid. `apps/web/test/import.test.mjs` runs the unclosed-WKT scenario.)
- [x] 7.4 Implement exporters (JSON, GeoJSON, KML, GPX, CSV, WKT, text, calculation sheet); verify round-trip import of each exported geographic format (all eight, as pure functions in `apps/web/src/lib/export.mjs`, behind a Download button on the answer card; the geographic four are offered only when the result holds a point. - [x] 7.5 Implement batch mode (100,000 rows, progress, cancel, per-row errors, joined export); verify the 10,000-row mixed-error scenario (every tool with a scalar input has a collapsed "Run many at once from a CSV" panel, loaded only when opened: columns map to inputs, suggested from the headers, with a unit for plain numbers per column; rows run in the compute worker 1,000 at a time through the core's own batch entry point, with progress and a Cancel that stops between chunks and keeps what was done; the errors are listed by line; and the download joins every original column to each output as a number with its unit in the header, plus an `error` column. `apps/web/test/batch.test.mjs` runs the 10,000-row, 12-error scenario end to end.)
