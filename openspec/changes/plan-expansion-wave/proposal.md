## Why

Nine expansion changes were written on 2026-10-19 after reading every current spec and the state of the catalog (357 tool ids built, 274 stable). They add to the product without changing what it is: the same two surfaces, the same core, no server compute, no live data, every tool cited and test-pointed. Without an order, the risk is the one `plan-launch-and-value-proof` named: breadth before depth. This change sequences the wave, states what each piece costs, and says when it starts.

It changes no behavior (`skip_specs: true`). The behavior lives in the nine changes.

## What Changes

- **An order for the wave,** cheapest and most-asked first, data-heavy last (`design.md`).
- **An entry rule:** a change starts only after the Phase 2 promotion work in its domain is not blocked by it, and its first tools go stable through the promotion recipe like any other.
- **A size accounting:** what each change adds to the operation rollup and to module and asset budgets.
