- [x] 1.2 Implement ambiguity detection with alternatives (order, exponent E, decimal comma, multi-grid strings); verify the ambiguity scenarios (built: order inference, the unlabeled-pair alternative, and decimal commas. Exponents are read rather than refused: a coordinate a machine exported, like `1.0E-3 2.0` or `-1.0523e2 4.001e1`, used to be turned away with "unexpected character 'E'", and the pair splitter cut such a pair in half because it counted every e as a hemisphere letter. There is no ambiguity to report inside one value, which is why this reads as a number and not as a warning: East only ever sits at an end of the text, and the ends come off before the number is scanned, so `1.5E` is still East and `1.5E2` can only be an exponent. An exponent past what a double holds is refused rather than carried on as infinity; pending: multi-grid ambiguity, which needs the other grid notations routed first (task 1.1), since MGRS and UTM are the only two the parser reaches today and they cannot collide. Done since: the `alternatives` output (parser 1.2.0), one row per other reading with whether it gives a coordinate and, when it does, the coordinate, so a caller can choose rather than parse a warning sentence: the other order when both are valid, the latitude-first reading when the first value cannot be a latitude, and commas as separators; the three ambiguity scenarios are pinned as vectors v023 to v025.
